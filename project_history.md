- **2026-07-30** — Added `/voice` hold-to-talk (Claude-Code-style) → Ollama endpoint transcription. Decision: target **`gemma4:e2b`** (native ~300M audio encoder) via Ollama's `/api/chat` with a base64 `audio` field. Rationale: Ollama exposes **no** `/v1/audio/transcriptions` endpoint and hosts **no audio-capable model on Ollama Cloud** (`ollama.com/search?c=cloud&c=audio` + live `/v1/models` probe confirm only `gemma4:31b` is available; `gemma4:e2b` and related tags return 404). Therefore `/voice` requires a **local Ollama instance** with an audio model pulled (`ollama pull gemma4:e2b`) and `OLLAMA_HOST` set. Cloud-only usage now fails fast with a clear message. Interaction: `/voice` *arms* voice mode; then **hold Space to talk, release to stop** (terminals report key-down only, so release is inferred from auto-repeat stopping — 700ms first-press threshold to ride out the terminal's initial repeat delay, 150ms once repeats arrive). Esc disarms. Module `koda/voice.py` (Recorder via `sounddevice` → 16kHz mono WAV → httpx POST to `{OLLAMA_HOST}/api/chat`); bridge dispatch `voice`/`voice_stop` (immediate, start/stop capture); TUI state machine idle→armed→recording→transcribing→armed, injects the transcript into the input via an `insertText` nonce prop on `<Input>`. **60s auto-stop cap** (`_MAX_SEC`, override via `OLLAMA_VOICE_MAX_SEC`) so a long hold can't produce a payload that times out on upload (32 KB/s PCM × 1.33 base64) or exceeds gemma4's audio-token budget — the audio-thread callback stops the stream and fires `on_cap`, which hops back to the bridge loop via `call_soon_threadsafe` to run the normal stop→transcribe flow and emit `voice_capped`. Optional extra `[voice]` adds `sounddevice`+`numpy` (needs `brew install portaudio` on macOS); `koda/voice.py` degrades gracefully if sounddevice/PortAudio missing.

- **2026-07-30** — **Reverted `/voice` entirely.** Removed `koda/voice.py`, the bridge's `voice`/`voice_stop` dispatch and `_voice_start`/`_voice_stop`/`_schedule_cap_stop`, the TUI state machine and push-to-talk key handling (`Input.tsx` ptt refs, `insertText` prop), the `/voice` slash command and completer entry, the wire events (`voice_recording`/`voice_capped`/`voice_transcribing`/`voice_result`), and the `[voice]` extra (`sounddevice`+`numpy`). Rationale: no working transcription backend. Ollama Cloud hosts no audio model; the local daemon is running but has zero models pulled; no `OPENAI_API_KEY`/`GROQ_API_KEY` configured. The macOS-native alternative (`SFSpeechRecognizer`) is blocked on TCC: a CLI process has no bundle, and neither Terminal.app nor VS Code declares `NSSpeechRecognitionUsageDescription`, so authorization can't be requested reliably from a terminal — and it would *add* a PyObjC dependency rather than remove Ollama. Two real bugs found and fixed before the revert, worth remembering if this is ever retried: (1) the max-seconds callback called `stream.stop()` from inside the audio callback, deadlocking the audio thread against `Recorder.stop()` — use `sounddevice.CallbackStop` instead; (2) that deadlock also meant the `on_cap` hook never ran, so the cap could never trigger transcription. Also cleaned up a stray `Users/badaralam/Desktop/KODA-Coding-Agent/` tree inside the repo (an OS-absolute path written through the project-rooted backend) containing an older `voice.py` and an uncleaned `_verify_voice.py`.
